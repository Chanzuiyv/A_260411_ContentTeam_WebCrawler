# 🕷️ 猫耳 FM 官方字幕弹幕爬虫（逐声计划 · 内容组）

> 从猫耳 FM（missevan.com）弹幕接口批量抓取 7 张虚拟偶像团综专辑的弹幕，**自动识别"官方字幕君"账号、提取带时间轴的字幕文本**，并按正剧 / 单人福利 / 歌曲三类分流输出，同步生成逐集质检报告。Python 实现，多线程 + 本地缓存 + 失败重试，一张配置表驱动全流程。
>
> 关键词：`Python` `requests` `XML 解析` `弹幕爬虫` `策略模式分类处理` `多线程` `规则识别官方账号` `CSV 质检报告`

---

## 一、项目背景 & 目标

"逐声计划"团综文字整理流水线的**第一道工序**（本项目 → 字幕格式转换 → 双路稿件合并）。

音频节目本身没有字幕文本，但猫耳 FM 的节目页面有一种特殊"弹幕"：官方字幕君会按时间轴发送 `角色名：台词` 格式的弹幕。纯人工整理需要逐集打开页面、从上万条观众弹幕中人工挑出官方字幕，成本极高。本项目解决：

1. **自动抓取**——只凭一张剧集信息表（节目 soundid 清单）批量拉取全部弹幕 XML；
2. **自动识别官方账号**——观众弹幕与官方字幕混杂，程序通过"该 UID 发送带角色名格式弹幕的频次"等规则反查官方字幕君 ID，无需人工记录账号；
3. **按节目类型分流**——正剧、单人福利、歌曲的提取策略不同，自动分类后进入不同输出目录，异常情况单独隔离待人工复核；
4. **质检可追溯**——每集输出一条报告记录（弹幕总数、官方弹幕数、官方 ID、异常原因等），异常集数一眼定位。

## 三、数据说明

### 1. 输入：剧集信息表（`test_input/剧集信息/`）

7 张专辑各一张 CSV（`FINE DAY`、`LASER出道日`、`NEW DAYS`、`WE FOUR`、`一起再出发`、`名利场`、`险象环声`），字段：

| 字段 | 含义 |
|---|---|
| `soundid` | 猫耳 FM 节目 ID（纯数字才会被处理；"没有"等空值自动跳过） |
| `filename` | 输出字幕文件名（即剧集标题） |
| `temporary_chars` | 本集非常驻/客串角色名单（逗号、顿号或空格分隔，"没有"视为空） |
| `other_chars` | 其他人物备注 |

当前表内有效剧集共 **645 集**（7 张表有效 soundid 行数合计）；同目录 `人物关系表_完整版.csv` 无 soundid 字段，会被自动忽略。

### 2. 数据来源接口

```text
GET https://www.missevan.com/sound/getdm?soundid={soundid}
```

返回标准弹幕 XML：每条 `<d p="时间戳,模式,字号,颜色,...,UID,...">弹幕文本</d>`，程序解析出 `(出现秒数, UID, 颜色, 文本)` 四元组。

### 3. 附：歌词参考库（`test_input/歌词库/`，50 个 txt）

人工整理的节目歌曲歌词文本，供歌曲类节目人工校对使用。

> ⚠️ `config.json` 中的 `lyrics_folder`、`song_similarity`（0.8）两个配置项为**歌词比对功能预留**，当前版本代码未引用——歌曲类节目统一输出空文件转人工处理（见下）。

## 四、处理流程

```
剧集信息 CSV（7 张表）
   │  读取 soundid / filename / 客串角色，过滤无效行
   ▼
按集分类（classifier.py）── song / solo / drama
   │
   ▼
取弹幕 XML（本地 24h 缓存命中则免请求，否则 requests 抓取，失败重试 3 次）
   │  XML → (时间, UID, 颜色, 文本) 列表
   ▼
分类处理器（策略模式：Drama / Solo / Song Handler）
   │  统计每个 UID 发送"角色：台词"格式弹幕的次数 → 反查官方字幕君 ID
   │  提取官方 ID 的全部弹幕 → 去噪去重 → 按时间排序
   ▼
写字幕文件（HH:MM:SS.ms - 文本）＋ 逐集写《异常报告.csv》
（4 线程并发，按专辑分组）
```

### 1. 剧集三分类规则（`classifier.py`）

| 类型 | 判定规则（按优先级） | 输出目录 |
|---|---|---|
| 歌曲 `song` | 文件名含"歌""曲" | `歌曲类_待人工处理/`（空文件占位） |
| 单人福利 `solo` | 非生日类且文件名含"福利/充电/提示音/电话语音"；或文件名中恰好出现 1 个已知角色名 | `单人福利/`（空字幕另移 `单人福利_空字幕/`） |
| 正剧 `drama` | 其余全部 | `正剧/`（官方 ID 超 20 个移入 `正剧_ID过多_待复核/`） |

### 2. 官方字幕君识别（核心规则）

程序不预设官方账号，而是用格式弹幕频次反查（`角色名：台词` 与 `【角色名】台词` 两种形式均识别，角色名限定为九位常驻角色 + 本集客串名单）：

- **正剧**：常驻角色的格式弹幕 **≥ 10 条**才认定该 UID 为官方（高可信阈值，防观众误打格式）；客串角色 ≥ 1 条即收录；
- **单人福利**：文件名锁定唯一角色时，取"发送该角色格式弹幕最多"的 UID，并列时以最早出现者为准；无法锁定时收录所有发过格式弹幕的 UID；
- 提取时自动过滤纯团名刷屏（`LASER`/`MANTA`）、角色名重复两/三次的喊话；正剧按 (UID, 内容) 去重，单人福利对重复 > 3 次的内容整体剔除。

### 3. 异常自动标记（写入 `异常报告.csv`）

报告共 23 列，主要标记：歌曲空文件待处理、正剧官方 ID > 20 个（疑似多人代打，隔离复核）、同一常驻角色关联 ≥ 3 个 ID、单人福利字幕超 15 条、锁定角色但无对应官方 ID、无官方 ID / 全部被过滤等，并附九位角色各自关联的 ID 数与请求 URL，方便逐集回查。

### 4. 输出字幕格式

```text
00:05:57.00 - 就这个镭塔爽
00:06:07.27 - 顾子尧：大家好，我们是——
00:06:21.58 - 林致：是的，尤其是入围这个奖项
```

即 `时:分:秒.百分秒 - 弹幕原文`，每行一条、按时间升序——正是下游"格式转换"工具的标准输入。

## 五、运行方式

1. 修改 [config.json](代码/config.json) 中的路径（当前为作者本机绝对路径）：

```json
{
    "table_folder": "剧集信息表所在目录",
    "output_root":  "字幕总输出目录",
    "max_workers": 4,
    "request_retries": 3,
    "cache_hours": 24
}
```

2. 在 `代码/` 目录下运行（程序以相对路径读取同目录 `config.json`）：

```bash
cd 代码
python mind.py
```

控制台逐集打印 `✅ 文件名 | 类型 | 官方弹幕:N`，每张专辑处理完生成一份 `异常报告.csv`。

> ⚠️ 注意事项：
> - **路径硬编码**：`config.json` 中四个路径需先改成本机路径；输出目录不存在会自动创建；
> - **输出不做清空**：重复运行会向分类子目录累加文件（移动/改名后的旧文件不会自动删除），正式跑批前建议手动清空输出目录；
> - **请求礼貌性**：4 线程并发、单请求 10 秒超时、失败重试 3 次间隔 1 秒；弹幕 XML 按 soundid 在系统临时目录缓存 24 小时，重复运行不重复请求；
> - 剧集表 CSV 编码自动尝试 `utf-8-sig / gbk / utf-8`；报告以 `utf-8-sig` 写出，Excel 直接打开不乱码；
> - 抓取内容仅用于个人学习与字幕整理，请遵守目标网站使用条款，勿高频请求或商用。

## 六、处理结果

当前剧集表（645 个有效剧集）单次运行的分流规则：每集产出 1 个字幕 txt + 在专辑报告中追加 1 行，共 5 类产出目录（正剧 / 正剧_ID过多_待复核 / 单人福利 / 单人福利_空字幕 / 歌曲类_待人工处理）。

仓库内 `test_output/` 与 `最终结果/` 为**真实生产运行快照**（内容一致）：各含 1307 个 txt 与 7 份异常报告，由两批运行产物叠加而成——

| 构成 | 数量 | 说明 |
|---|---|---|
| 专辑根目录平铺字幕 | 642 个 txt | 早期版本（未做分类分流）的输出，也是下游格式转换项目的实际输入 |
| `正剧/` | 297 个 | 分类版本输出 |
| `单人福利/` | 189 个 | 同上 |
| `单人福利_空字幕/` | 89 个 | 单人福利未识别到官方字幕的空文件 |
| `歌曲类_待人工处理/` | 67 个 | 歌曲类空文件占位 |
| `正剧_ID过多_待复核/` | 23 个 | 官方 ID 超阈值隔离件 |

> 📌 技术要点小结：本项目的关键不是"发请求"，而是**在没有官方账号名单的前提下，用"格式弹幕频次阈值 + 角色名单匹配"把官方字幕君从海量观众 UID 中可靠地反查出来**；再用策略模式隔离三类节目的提取逻辑、用分类目录 + 多维异常报告把"机器不确定"的部分显式交给人工，构成"自动跑批—异常隔离—人工复核"的可运营闭环。
